## Summary

A person submits the new owner registration form with their personal details. If the details pass all validation checks, a new owner record is saved and the person is taken to the newly created owner's profile page. If any details are invalid, the form is redisplayed with an error message.

## Actor and triggers

- **Actor:** Visitor or unauthenticated user (no access restrictions are enforced on this endpoint)

- **Trigger:** The user submits the 'New Owner' form by clicking the create/submit button

## Preconditions

- The user has navigated to and filled in the new owner registration form
- The form data is submitted via HTTP POST to the owner registration endpoint

## Main flow

1. The user submits the new owner form with all required personal details (e.g. name, address, telephone). [^step1]
2. The system validates all submitted fields against the owner data rules (e.g. required fields, format constraints). [^step2]
3. If all fields are valid, the system saves the new owner record to the database. [^step3]
4. The system sets a success notification message ('New Owner Created') to be displayed to the user. [^step4]
5. The user is redirected to the newly created owner's profile page. [^step5]

## Alternate and exception flows

- **Validation failure:** If any submitted field fails validation (e.g. a required field is blank or incorrectly formatted), the system sets an error notification message ('There was an error in creating the owner.') and redisplays the registration form so the user can correct their input. No record is saved.

## Postconditions

- On success: a new owner record exists in the database and the user is viewing that owner's profile page
- On failure: no new record is created, and the registration form is shown again with an error message

## Business rules

- The 'id' field and any nested 'id' fields on the submitted form are always ignored, even if present in the request. The system assigns the ID automatically after saving. [^rule1]
- All standard owner data validation rules (e.g. required fields, length limits) must pass before the record is saved. The specific rules are defined on the Owner data model. [^rule2]
- This endpoint has no authentication or authorisation controls; any user who can reach the form URL can create an owner record. [^rule3]

## Suggested test scenarios

- **Happy path — all fields valid** — Given a user has filled in all required owner details correctly, when they submit the new owner form, then a new owner record is created, a success message is shown, and the user is redirected to the new owner's profile page.
- **Validation failure — required field missing** — Given a user has left one or more required fields blank on the new owner form, when they submit the form, then no owner record is created, an error message is displayed, and the registration form is shown again.
- **Attempted ID injection** — Given a user submits the new owner form with a manually set 'id' field in the request, when the form is processed, then the submitted ID value is ignored and the system assigns its own ID to the new record.
