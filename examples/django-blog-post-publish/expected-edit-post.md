## Summary

A signed-in author opens the edit form for one of their own posts, changes the title, body, or category, and saves. The system ensures only the post's owner can reach the edit form and confirms the save with a success message.

## Actor and triggers

- **Actor:** Signed-in author who owns the post.
- **Trigger:** The author navigates to `/blog/posts/{pk}/edit/` (GET) and submits the edit form (POST).

## Preconditions

- The author is authenticated.
- The post exists and was created by the signed-in author.

## Main flow

1. The author navigates to the edit URL for their post.
2. The system fetches the post, confirming the signed-in user is its author.[^queryset]
3. The system renders the edit form pre-populated with the post's current `title`, `body`, and `category`.
4. The author modifies one or more fields and submits the form.
5. The system validates the submitted values.
6. If validation passes, the system saves the updated post and shows a success message ("Post updated."), then redirects to the post's detail page.

[^queryset]: `get_queryset()` returns `Post.objects.filter(author=self.request.user)`. A request for a post owned by someone else resolves to a 404, not a 403, so no information about other authors' posts is disclosed.

## Alternate and exception flows

- **Validation failure:** If a required field is missing or invalid, the form is re-displayed with error messages and the author's partial input preserved. No changes are saved.
- **Wrong author / not found:** The system returns 404. The author cannot determine whether the post exists but belongs to another user.
- **Unauthenticated:** Django's `LoginRequiredMixin` (or the session middleware) redirects to the login page.

## Postconditions

- The post row reflects the author's changes.
- The author sees a one-time "Post updated." message.
- `status` and `published_at` are unchanged by this operation (editing a published post does not unpublish it).

## Business rules

- **Only the author can edit their own posts.** The `get_queryset()` scope prevents accessing another user's post.
- **Editing does not change publication status.** A PUBLISHED post that is edited remains PUBLISHED. A DRAFT post that is edited remains DRAFT.
- **Only `title`, `body`, and `category` are editable through this form.** Fields such as `author`, `status`, `published_at`, and `created_at` are not exposed and cannot be changed here.

## Suggested test scenarios

- **Happy path** -- Given a signed-in author with their own post, when they submit valid edits, then the post is updated and a success message is shown.
- **Wrong author** -- Given user B's post, when user A tries to edit it, then the system returns 404 and the post is unchanged.
- **Validation failure** -- Given an edit form with an empty title, when submitted, then the form is re-shown with an error and the post is unchanged.
- **Published post edit** -- Given a PUBLISHED post, when the author edits the body, then the post status remains PUBLISHED after the save.
