# examples/

Worked examples of input source code → output use-case Markdown. Each example is a directory containing:

- `source.md` — pointer to the upstream source file and the specific function/region documented
- `expected.md` — the canonical Markdown output we want code2wiki to produce (hand-curated gold standard)
- `notes.md` — what makes this example interesting (edge cases tested, language quirks, etc.)
- `baseline.snapshot.json` — structural fingerprint of `expected.md` (sections, frontmatter keys, body line count, content hash, separate managed-block hash). Generated by `scripts/gen-baseline-snapshots.mjs`. Don't edit by hand.

These examples serve three purposes:

1. **Spec** — they define what "good output" looks like for the prompt engineer
2. **Regression suite (two layers)** — both layers implement signal #2 from [`docs/self-learning.md`](../docs/self-learning.md):
   - **Layer 1 (default, runs on every `npm test`):** `src/core/feedback/examples.test.ts` recomputes the snapshot from each `expected.md` and asserts it matches the committed `baseline.snapshot.json`. Pure-stdlib check; no LLM call required; runs in <1s. Catches accidental edits to the curated file.
   - **Layer 2 (gated, real LLM):** `src/core/feedback/examples.live.test.ts` spawns `code2wiki generate --only <name>` against the cloned upstream source, then asserts engine output is shaped the same as the baseline (sections + frontmatter keys exact; body line count ±25%; content hashes ignored). Run via `CODE2WIKI_RUN_LIVE_EXAMPLES=1 npm run test:live-examples`. Needs `ANTHROPIC_API_KEY` and the relevant `references/<repo>/` clone (gitignored per ADR-010); skips a case if the local clone is missing rather than failing the whole suite.
3. **Marketing** — each example becomes a public landing page or blog post

## How to add a new example

1. Create a new directory under `examples/`
2. Copy the upstream source file pointer into `source.md`
3. Hand-write the ideal `expected.md` following [`docs/usecase-template.md`](../docs/usecase-template.md)
4. Add a `notes.md` explaining what makes it interesting
5. Run `npx tsx scripts/gen-baseline-snapshots.mjs` to generate `baseline.snapshot.json` for the new example
6. The regression test suite picks the new example up on the next `npm test` run

## Updating an existing example

When you intentionally edit a hand-curated `expected.md` (e.g., to reflect a deliberate spec change), regenerate the baseline alongside it:

```sh
npx tsx scripts/gen-baseline-snapshots.mjs
```

Commit the updated `expected.md` AND `baseline.snapshot.json` together. The test will fail loudly if the snapshot drifts without the baseline being updated.
